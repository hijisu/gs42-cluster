# 시안과 구현의 차이 (Phase 0~2)

`design/*.dc.html` 시안은 출발점이고 구현하며 달라질 수 있다(AGENTS.md). 이 문서는 Phase 0~2 구현에서 시안과 달라진 점과 이유를 화면별로 정리한 목록이다. 시안 파일 자체는 수정하지 않았다.

## 공통

| 항목 | 시안 | 구현 | 이유 |
| --- | --- | --- | --- |
| 임시 홈(`/`) | 현황 카드가 있는 대시보드 | 면담/회의실 바로가기만 있는 임시 홈 | 홈 대시보드는 Phase 3 (#30, #31) |
| 사이드바 | 사용자·화면 전환 | 알림 벨(안 읽은 수)·로그아웃 추가, 화면 전환 토글은 운영팀 계정에만 노출, 본문 바로가기 링크 | 앱 안 알림(#59), 인증(#9), 접근성(#26) |
| 모바일 사이드바 | 사용자 영역 숨김 | `intra_id`만 작게 표시 | 로그인한 계정 확인 |
| 모달 | 단순 팝업 | Esc·배경 클릭 닫기, 포커스 이동·순환·복귀 | 키보드 접근성 |
| 상태 표시 | 고정 문구 | 서버가 주는 상태 코드를 프론트 사전(`labels.ts`)으로 문구·색 매핑 | AGENTS.md(API는 코드만) |
| 시각 | 고정 예시 | 서버 UTC를 KST로 변환(`lib/datetime.ts`) | API 계약 |

| 화면 | 달라진 점 | 이유 |

## 접근성·반응형 점검 결과 (#26)

- **대비**: 토큰 조합을 WCAG 명암비로 계산해 일반 텍스트 4.5:1 미만이던 '마감·미개설 격자 셀'(2.95)을 `--c-muted`(5.7)로 교정. 나머지 조합은 4.65 이상.
- **키보드**: 전역 `:focus-visible` 윤곽선, 본문 바로가기 링크, 모달 포커스 순환·복귀, 현재 메뉴 `aria-current`, 칩/탭의 `aria-pressed`·`aria-selected`.
- **반응형(≤900px)**: 사이드바가 상단 가로 바로 바뀌고 2단 레이아웃(`split`, `g2~g4`)이 1열로 접힘. 표·타임라인·시간 격자는 각자 가로 스크롤 컨테이너 안에서만 넘침. 행(`row`)은 좁으면 줄바꿈.
- **PWA 설치**: 192/512 PNG 아이콘(maskable 포함)과 apple-touch-icon 추가.
- **움직임**: `prefers-reduced-motion`이면 애니메이션 제거.
- **360px 실측(#87)**: 처음 점검에서는 브라우저 확인 없이 CSS만 점검해 실제로는 화면이 깨져 있었다(문서 가로 폭 610~683px). Chrome DevTools Protocol로 모바일 에뮬레이션(360px)을 켜고 라우트마다 `documentElement.scrollWidth == clientWidth`와 스크린샷을 확인하는 방식으로 다시 점검해 아래를 고쳤다. 개발 서버(`npm run dev`)에 `API_PROXY_TARGET`으로 목 API를 연결해 측정했고, 교육생 `/` `/meeting` `/room` `/reviews`, 운영팀 `/staff` `/staff/meeting` `/staff/room` `/staff/courses`, `/login`이 모두 360px에서 가로 넘침이 없다.
  - `.sr-only`가 좌표 없이 `position:absolute`라 가로 스크롤 메뉴 안에서도 잘리지 않고 문서를 넓힘 → 좌표 고정
  - `.review-split`이 모바일 1열 규칙보다 뒤에 정의되어 2열 유지 → 모든 split 변형을 마지막 미디어 쿼리에서 1열로
  - 모바일에서 사이드바가 행 stretch로 화면 높이만큼 늘어남 → 행 높이 고정, 상단 바(계정·알림·화면 전환·로그아웃)를 한두 줄로 압축
  - 타임라인 장소 열·최소 폭 축소(≤480px)
- **미확인**: 실제 기기에서의 터치 조작, 스크린리더 낭독, PWA 설치 동작. 테스트(88개)는 DOM 구조·접근성 이름·키보드 동작까지만 검증하고 CSS 레이아웃은 검증하지 않는다.
