# 시연 가이드 (DEMO)

해커톤 핵심 시연 두 가지를 **처음부터 끝까지** 따라 하는 문서입니다.

1. **회의실 예약**: 교육생 로그인 → 예약 요청 → 운영팀 승인 → 교육생이 결과·이용수칙 확인
2. **면담 신청**: 교육생 신청 → 운영팀 담당자 배정 → 일정(장소) 확정 → 교육생이 결과 확인

실행 환경(Docker, `.env`)은 [BUILD.md](BUILD.md)를 먼저 따릅니다.

## 1. 준비 (약 1분)

```bash
cp .env.example .env                       # 처음 한 번
docker compose up -d --build               # DB·백엔드·프론트·프록시
docker compose exec backend python manage.py seed_demo --reset
# 위 세 줄 대신 `make dev`(기동 + 시연 데이터 + 도서)와 `make demoreset`(시연 데이터 초기화)을 써도 됩니다.
```

`seed_demo`는 시연용 데이터를 한 번에 준비합니다(여러 번 실행해도 안전, `DJANGO_DEBUG=true`에서만 동작).

| 준비되는 것 | 내용 |
| --- | --- |
| 면담 | 모의 운영팀(`staff`)을 기본 담당자로 지정, **평일 10·11·13·14·15·16시** 가능 시간(앞으로 7일) |
| 회의실 | 다음 평일에 `다목적회의실` 10–12시 **승인된 예약 1건**, 같은 장소 11–13시 **겹치는 대기 요청 1건**(운영팀 화면에 충돌 표시), `유니버스룸(소)` 15–17시 대기 요청 1건 |
| 교육과정·후기 | 교육과정 3개와 참여자(`student`, `intra_a`, `intra_b`), 후기 예시 |

`--reset`은 **모의 계정 `student`·`staff`의 면담 신청·회의실 예약·후기·알림만** 지웁니다(다른 데이터와 브라우저에 붙은 푸시 구독은 그대로). 시연을 다시 처음부터 하고 싶을 때마다 실행하세요.

## 2. 시연 시나리오

브라우저 창 **두 개**를 씁니다: 교육생용(일반 창)과 운영팀용(시크릿 창 등 쿠키가 분리된 창). 둘 다 http://localhost:5173 에 접속해 로그인 화면의 **"개발용 모의 로그인"**에서 각각 `교육생` / `운영팀`을 누릅니다.

### 시나리오 1 — 회의실 예약

| # | 누가 | 화면 | 동작 | 기대 결과 |
| --- | --- | --- | --- | --- |
| 1 | 교육생 | 회의실 예약(`/room`) | 이용수칙·현황표를 본다. 날짜를 고르고 장소·시작·종료·목적·인원을 입력 후 **예약 요청하기** | "내 예약 요청"에 **승인 대기**로 나타난다. 현황표에 대기로 표시된다 |
| 2 | 운영팀 | 회의실 관리(`/staff/room`) | 대기 요청 카드에서 방금 요청을 찾는다(시드의 겹치는 요청에는 **시간 충돌** 표시가 붙어 있다) | 교육생 이름과 요청 내용이 보인다 |
| 3 | 운영팀 | 같은 화면 | **승인 · 이용수칙 전송** (겹치면 *대체 장소로 승인*, 불가하면 반려+사유) | 요청이 승인 목록으로 이동한다. 이미 승인된 예약과 겹치는 요청은 승인할 수 없다 |
| 4 | 교육생 | 회의실 예약 / 사이드바 벨 | 벨의 알림을 확인한다 | "회의실 예약이 확정되었어요" 알림, 내 예약이 **승인됨**으로 바뀐다 |
| 5 | 교육생 | 내 예약 요청 | **이용수칙 확인** | 이용수칙 팝업이 뜬다. 현황표에서 해당 시간이 **예약 확정**으로 보인다 |

### 시나리오 2 — 면담 신청

| # | 누가 | 화면 | 동작 | 기대 결과 |
| --- | --- | --- | --- | --- |
| 1 | 교육생 | 면담 신청(`/meeting`) | ①면담 유형 ②희망 시간(가능/마감 표시) ③신청 내용을 입력하고 **면담 신청하기** | "내 신청 내역"에 **배정 중**으로 나타난다 |
| 2 | 운영팀 | 면담 관리(`/staff/meeting`) | 요청 카드에서 방금 신청을 찾아 **담당자**를 고르고 장소를 입력한다 | 교육생 이름·유형·희망 시간이 보인다 |
| 3 | 운영팀 | 같은 화면 | **희망 일시로 확정** (시간 조정이 필요하면 *다른 시간 제안*) | 확정되면 같은 담당자·같은 시각의 다른 요청은 확정할 수 없다 |
| 4 | 교육생 | 면담 신청 / 사이드바 벨 | 알림과 내 신청 내역을 확인한다 | "면담이 확정되었어요" 알림, 상태 **확정**, 확정 일시·담당·장소가 표시된다. 그 시간은 **마감**으로 바뀐다 |

## 3. 자동 점검 (화면 대신 API 수준)

위 두 시나리오를 **같은 API 호출 순서**로 실행·검증하는 스크립트입니다(프론트 프록시를 통해 실제 스택에 요청). 끝나면 만든 신청·예약을 스스로 취소해 원래 상태로 되돌리므로 **반복 실행**할 수 있습니다.

```bash
python3 scripts/e2e_demo.py --runs 2          # 처음부터 끝까지 2회
python3 scripts/e2e_demo.py --base http://localhost:8000 --runs 2 --skip-spa   # 호스트에서 runserver 로 띄운 백엔드 직접(compose 백엔드는 호스트에 포트를 열지 않음)
```

- 한 회차에 33개 단계를 검사합니다: 로그인, 운영 API 권한(교육생 403), 이용수칙, 현황표 셀 상태, 요청→승인/배정·확정 상태 변화, 알림 도착·읽음, 슬롯 마감/복구, 취소.
- 실패하면 어느 단계인지 한 줄로 알려 주고 종료 코드 1을 돌려줍니다. 서버가 없거나 모의 로그인이 꺼져 있으면(운영 모드) 원인을 설명합니다.
- 같은 시나리오가 CI에도 있습니다(`backend/tests/test_e2e_demo_script.py`, 임시 서버에서 2회 연속 실행).

## 4. 2회 확인 체크리스트

완료 조건은 **두 시나리오를 처음부터 끝까지 2회 무사고로 재현**하는 것입니다. 회차 사이에 `seed_demo --reset`을 실행하세요.

| 확인 | 1회 | 2회 | 담당 |
| --- | --- | --- | --- |
| 자동 점검 `scripts/e2e_demo.py --runs 2` 통과 | ☑ | ☑ | h-be (API·권한·알림) |
| 시나리오 1을 두 브라우저 창에서 화면으로 수행 | ☑ | ☑ | 사람 / 브라우저 권한이 있는 에이전트 |
| 시나리오 2를 두 브라우저 창에서 화면으로 수행 | ☑ | ☑ | 사람 / 브라우저 권한이 있는 에이전트 |
| 모바일 폭(좁은 화면)에서 두 시나리오의 화면이 깨지지 않는다 | ☐ | ☐ | s-ui (#26) |

자동 점검 칸은 개발 스택(프록시 경유)에서 2회 연속 통과를 확인한 결과입니다. 화면 칸은 2026-10-17에 사람이 두 브라우저 창으로 2회 수행해 확인했습니다(앱 안 알림·푸시 알림 도착 포함). 모바일 폭 칸은 #26에서 확인합니다.

## 5. 알려진 한계

- **실제 42 로그인은 아직 확인하지 못했습니다**(UID/SECRET 필요, #8). 시연은 개발용 모의 로그인으로 진행합니다. 운영 모드(`DJANGO_DEBUG=false`)에서는 모의 로그인이 꺼집니다.
- **웹 푸시 실수신**은 실제 브라우저·푸시 서비스가 필요해 자동으로 확인하지 못했습니다(#60). 앱 안 알림(벨)은 항상 동작합니다. Slack 알림은 Phase 3입니다.
- 면담 가능 시간은 시연 데이터가 열어 둔 평일 시간뿐이고, **지난 시간은 마감**으로 보입니다. 날짜가 바뀌면 `seed_demo`를 다시 실행해 앞으로의 시간을 열어 주세요.
- 시각은 서버에서 UTC로 주고 화면에서 한국 시간(KST)으로 표시합니다.

## 6. 문제가 생기면

| 증상 | 확인 |
| --- | --- |
| 로그인 화면에 모의 로그인 버튼이 없다 | 프론트가 개발 서버(`npm run dev`/compose)인지, 백엔드가 `DJANGO_DEBUG=true`인지 |
| 면담 가능 시간이 비어 있다 / "신청 가능한 시간이 있다" 단계 실패 | `seed_demo` 실행(날짜가 지났다면 다시) |
| 운영 화면에서 요청이 보이지 않는다 | 운영팀 창과 교육생 창의 로그인이 서로 다른지(같은 창이면 마지막 로그인으로 덮어쓴다) |
| `.env`를 바꿨는데 반영되지 않는다 | `docker compose up -d`(`restart`는 `.env`를 다시 읽지 않는다) |
| 스크립트가 "서버에 연결할 수 없습니다" | `docker compose ps`, 포트(`FRONTEND_HOST_PORT`) 확인 후 `--base`로 주소 지정 |
