# 42경산 캠퍼스 환경 개선을 위한 서비스 개발 공모전 개발 계획서

- 팀명: hisong's team
- 서비스명: 42gs-cluster
- 프로젝트 핵심 키워드: 42경산 클러스터 통합 시스템 (면담 신청, 회의실 예약, 오아시스 도서 관리, gs42stats, 스크린락 20분 타이머, 음료냉장고 이용, 프로젝트/교육과정 후기 공유)

## 1. 개발 동기 및 필요성
캠퍼스 생활 또는 학습 중 인지한 불편 사항, 비효율적인 프로세스,
문제가 발생한 배경, 개발자 관점에서의 해결 필요성을 서술하세요.

**배경**
- 면담, 회의실 예약, 도서 이용, 자리·음료냉장고 관리 등 클러스터 생활 절차가 대부분 슬랙 문의 및 수기 방식으로 처리됨
- 교육생·페다고 팀 모두 동일 내용을 반복 확인·조정해야 하는 비효율 발생

**① 신청·예약 비정형화 (면담, 회의실)**
- 면담·장소 대여를 #pedagogy 채널에 문의 → 사유 및 일시 재확인을 페다고 팀이 대댓글로 처리
- 회의실 예약 현황을 볼 수단 부재 → 중복 예약 시 수기 조정

**② 규칙 확인의 수작업 의존 (자리 사유화, 음료냉장고)**
- 스크린락 20분 초과 후 자리 미정리 시 tig 대상이나, 시간 확인은 본인 책임
- 음료냉장고 1일 초과 보관 시 tig 대상이나, 네임펜 기록은 식별이 어렵고 페다고 팀이 매일 수기 점검

**③ 정보 접근성·축적 부재 (도서, 통계, 후기)**
- 오아시스 도서 목록이 종이로만 비치되어 검색 불가
- 반출 금지에도 분실 발생 → 자체 운영 중인 42gslib로 목록 열람은 해결했으나 통합 시스템은 부재
- 학습 통계(42Stat, 42서울 오픈소스)가 별도 주소로 분산 운영
- 기업 연계 프로젝트·교육과정 후기가 기수 교체(2년 주기)로 축적되지 않음

**개발자 관점의 해결 필요성**
- 공통 원인: ①비정형 텍스트로 자동 검증·집계 불가 ②현재 상태(예약·보관 현황)를 담는 단일 저장소 부재 ③명확한 규칙(20분, 1일)의 자동화 미비 ④서비스·정보의 분산
- 개별 기능 단위 개선이 아닌, 정형 데이터 저장소와 인증을 공유하는 통합 시스템 구축이 필요
- 통합 구조는 기능 확장 시 재사용성을 높이고, 차기 기수로의 인수인계도 용이하게 함

## 3. 기술 아키텍처 및 구현 로드맵

**기술 스택**

| 구분 | 기술 | 비고 |
| --- | --- | --- |
| Frontend | 리액트 기반 반응형 웹 + PWA | OS 무관, 홈 화면 설치 시 푸시 수신 |
| Backend | Django REST API | 예약 충돌 검증, 알림 스케줄링 |
| DB | PostgreSQL + Redis | 예약·신청·음료 기록·후기 등 정형 데이터 |
| 인증 | 42 OAuth | 교육생 권한 API 범위 내 사용 |
| 알림 | Web Push | 20분 타이머, 음료 만료 안내, 예약·면담 안내 |
| 배포 | AWS, HTTPS | 푸시 발송에 HTTPS 필수 |

네이티브 앱 대신 PWA를 택한 이유는 안드로이드와 iOS를 별도로 개발하지 않고도 하나의 코드로 푸시 알림까지 제공할 수 있기 때문입니다. (iOS는 홈 화면에 설치한 경우에 푸시를 수신하므로 설치 안내를 함께 제공합니다.)

## 5. 기대 효과 및 캠퍼스 활용 방안

**교육생**
- 면담 신청, 회의실 예약, 도서 검색을 한 곳에서 처리하여 슬랙 문의·답변 대기 감소
- 회의실 예약 현황 사전 확인으로 중복 예약 및 재조율 방지
- 20분 타이머, 음료 만료 알림으로 tig 대상이 되는 실수 예방

**페다고 팀(운영진)**
- 정형 양식 접수로 사유·일시 재확인 업무 감소
- 예약·음료 보관 현황을 관리 화면에서 일괄 확인하여 냉장고 수기 점검 대체
- 신청·이용 기록이 쌓여 운영 현황 집계 및 개선 근거로 활용 가능

**42경산 커뮤니티**
- 기수가 바뀌어도 후기와 이용 기록이 남아 경험이 축적됨
- 선배 기수의 후기를 통해 아시아 해커톤, 글로벌 연수 등 반복 프로그램의 참여 판단 및 참여도 제고 기대
- 교육생이 직접 만들고 사용하며 개선하는 42경산 자치 문화의 사례

**활용 방안**
- 해커톤 이후 핵심 기능(회의실 예약, 음료냉장고)부터 파일럿 운영 → 사용자 피드백 반영 → 정식 서비스 전환
- 도입 효과는 슬랙 문의 건수, 중복 예약 건수, 만료 음료 건수의 전후 비교로 확인
