# 시안과 구현의 차이 (Phase 0~2)

`design/*.dc.html` 시안은 출발점이고 구현하며 달라질 수 있다(AGENTS.md). 이 문서는 Phase 0~2 구현에서 시안과 달라진 점과 이유를 화면별로 정리한 목록이다. 시안 파일 자체는 수정하지 않았다.

## 모바일 설계 (≤900px, #26)

시안(`design/*.dc.html`)에는 `@media (max-width:900px)` 한 블록뿐이고 '사이드바를 상단 바로 바꾸고 격자를 1열로 쌓기'가 전부라 모바일은 사실상 설계되지 않았다. 구현이 이를 그대로 따르자 360~375px에서 헤더가 화면의 20%를 차지하고 타임라인이 잘리는 등 깨졌다(#87, #26 코멘트). 모바일을 따로 설계했다.

| 영역 | 데스크톱(>900px) | 모바일(≤900px) |
| --- | --- | --- |
| 내비게이션 | 좌측 사이드바 | **56px 상단 바**(☰ 메뉴 · 로고 · 알림 · 계정) + **좌측 드로어**(메뉴 · 계정 · 화면 전환 · 로그아웃). 사이드바는 렌더링하지 않음 |
| 알림 | 사이드바의 벨 + 문구 | 상단 바의 아이콘형 벨(안 읽은 수 배지) |
| 회의실 타임라인 | 장소 열 + 13칸 | 장소 이름 아래에 13칸 바(가로 스크롤 없이 09~21시 전체) |
| 시간 격자(면담) | 날짜 4열 | 날짜 열 최소 44px, 좁으면 가로 스크롤 |
| 탭·필터 | 줄바꿈 | 가로 스크롤(줄바꿈으로 항목이 홀로 남지 않게) |
| 터치 대상 | 36~44px | 최소 44px(칩·버튼·탭·메뉴·체크박스), 글자 최소 12px |
| 2단 레이아웃 | 본문 + 360px 패널 | 1열 |

구현: `components/Layout.tsx`가 `useMediaQuery('(max-width: 900px)')`로 사이드바/상단 바+드로어 중 하나만 렌더링하고(`lib/useMediaQuery.ts`), 드로어는 `Modal`의 `placement="left"`(포커스 이동·순환·복귀·Esc 포함)를 쓴다.

## 접근성·반응형 점검 결과 (#26)

- **대비**: 토큰 조합을 WCAG 명암비로 계산해 일반 텍스트 4.5:1 미만이던 '마감·미개설 격자 셀'(2.95)을 `--c-muted`(5.7)로 교정. 나머지 조합은 4.65 이상.
- **키보드**: 전역 `:focus-visible` 윤곽선, 본문 바로가기 링크, 모달·드로어 포커스 순환·복귀, 현재 메뉴 `aria-current`, 칩/탭의 `aria-pressed`·`aria-selected`.
- **움직임**: `prefers-reduced-motion`이면 애니메이션 제거.
- **PWA 설치**: 192/512 PNG 아이콘(maskable 포함)과 apple-touch-icon.
- **실측(Chrome DevTools Protocol 모바일 에뮬레이션)**: 320 / 375 / 414px에서 교육생 `/` `/meeting` `/room` `/reviews`, 운영팀 `/staff` `/staff/meeting` `/staff/room` `/staff/courses`(목 API 연결)를 측정했다. 기준: 문서 가로 넘침 0, 모바일 헤더 ≤64px(실측 56px), 44px 미만 터치 대상 0개, 12px 미만 글자 0개.
  - 예외: **320px의 `/room` 달력**은 7열 구조상 날짜 칸이 36px(WCAG 2.2 SC 2.5.8 최소 24px 충족, 권장 44px 미달). 375px부터는 44px.
- **CSS 검증**: `vite build`와 vitest는 짝이 안 맞는 중괄호 같은 CSS 오류를 잡지 못한다(실제로 편집 실수로 개발 서버에서 CSS 전체가 실패했다). `src/styles/styles.test.ts`가 모든 CSS를 파싱하고 정의되지 않은 토큰 사용을 검사한다.
- **미확인**: 실제 기기(iOS Safari·Android Chrome)의 터치 조작, 스크린리더 낭독, PWA 설치 동작. 측정은 에뮬레이션이다.

### #122 면담 시간 제안

운영팀의 다른 시간 제안은 30분 간격 대신 분 단위 자유 입력을 지원합니다. 미래 시각 검증은 유지합니다.

### #123 면담 제안 수락

교육생 내 면담 신청 내역에 제안 일시와 수락(확정하기) 버튼을 표시합니다. 수락 시 제안된 시각으로 확정하며, 실패하면 상태를 다시 조회하고 안내합니다.

### #116 프로필 사진

42 로그인 프로필 사진을 사이드바 계정 아바타에 표시합니다. 사진이 없거나 로드에 실패하면 기존 이니셜을 사용합니다.

### #118 도서 서가 위치 제거

교육생 도서 카드·상세와 운영팀 도서 표·추가/수정 폼에서 서가 위치를 제거합니다. 도서의 다른 정보와 신고·희망 도서 기록은 유지합니다.

### #119 도서 페이지네이션

교육생 도서 검색과 운영 도서 관리에 20종 단위 이전/다음 페이지를 추가합니다. 검색·분류 변경은 첫 페이지로 돌아가며 교육생 페이지는 URL에 보존합니다.

### #120 운영 면담 가능 시간 설정

모달의 시간 칩 목록 대신 카드 안에서 주/일 단위 칸 그리드로 직접 설정합니다. 마우스는 드래그, 터치·키보드는 탭으로 칸을 열고 닫으며, 날짜·시작·종료를 골라 범위로 열기/닫기도 할 수 있습니다. 직접 설정한 날은 헤더에 표시하고 "기본값으로 되돌리기"로 평일 10~12·13~17시 기본값을 복원합니다(#121 API). 저장하지 않은 변경이 있으면 날짜 이동을 막습니다. 모바일(≤900px)은 일 단위가 기본입니다.

### #127·#128 교육과정 상태 제거와 수정

등록 폼의 "상태" 선택과 표의 "종료 · 후기 열기" 버튼을 제거합니다. 상태는 서버가 날짜로 계산해(시작 전/진행 중/종료일 이후 후기 수집) 표에만 표시하고, 후기는 종료일 이후부터 마감일 전까지 받습니다. 표의 "수정" 버튼으로 연 모달에서 과정 정보·후기 마감일을 고치고 참여 학생을 추가/제거할 수 있으며, 후기를 쓴 참여자를 제거하면 후기는 남고 작성률에서만 빠진다는 확인 문구를 보여줍니다.

### #126 회의실 예약 차단 기간(반복)

운영 회의실 관리 화면 하단에 "예약 차단 기간" 카드를 추가합니다. 장소·날짜·시간(30분 단위)·반복(없음/매일/매주+요일/평일)·반복 종료일·사유로 캘린더 일정처럼 차단을 만들고, 목록에서 회차를 펼쳐 한 회차만 수정·삭제하거나 전체를 수정·삭제합니다. 저장 전에 서버에 먼저 확인(check_only)해 겹치는 기존 예약이 있으면 목록으로 경고하고 확인 후 저장합니다(기존 예약은 자동 취소되지 않음). 예약 현황 타임라인에는 차단 장소·시간·사유를 안내 문구로 덧붙입니다(교육생 화면 포함).

### #156 확정·승인된 건의 취소 버튼 제거

교육생 "내 면담 신청"은 배정 중·시간 조율 중에만, "내 예약 요청"은 승인 대기에만 취소 버튼을 보여줍니다. 확정/승인된 건에는 버튼 대신 목록 아래 안내("확정된 면담은 취소할 수 없어요. Slack #pedago로 문의해 주세요." / "승인된 예약은 취소할 수 없어요. 운영팀에 문의해 주세요.")를 두고, 서버가 not_cancelable(409)로 거절하는 경우도 같은 문구로 보여줍니다.
