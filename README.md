# 42경산 캠퍼스 환경 개선을 위한 서비스 개발 공모전 개발 계획서

- 팀명: hisong's team
- 서비스명: 42gs-cluster
- 프로젝트 핵심 키워드: 42경산 클러스터 통합 시스템 (면담 신청, 회의실 예약, 오아시스 도서 관리, gs42stats, 교육과정 후기 공유) · 교육생 / 교육운영팀 화면 분리

## 1. 개발 동기 및 필요성
캠퍼스 생활 또는 학습 중 인지한 불편 사항, 비효율적인 프로세스,
문제가 발생한 배경, 개발자 관점에서의 해결 필요성을 서술하세요.

**배경**
- 면담, 회의실 예약, 도서 이용 등 클러스터 생활 절차가 대부분 슬랙 #pedago 채널 문의 및 수기 방식으로 처리됨
- 교육생·교육운영팀 모두 동일 내용을 반복 확인·조정해야 하는 비효율 발생

**① 면담 신청**
- 정해진 양식 없이 면담 가능 여부·목적·비대면 여부를 #pedago 채널에 작성 → 교육운영팀이 담당자 확인 후 날짜를 정해 회신
- 본래 문의 내용을 FAQ처럼 공유하려는 취지였으나, 교육생들이 면담 사유 공개를 꺼려 공개 질문은 거의 없고 개인 면담 위주로 운영됨
- 사유·유형이 빠진 문의가 많아 담당자 배정과 일정 확인을 위한 재문의가 발생

**② 회의실 예약**
- 목적·일시·장소·인원·기타 요청사항을 슬랙 메시지로 작성 → 교육운영팀이 예약 가능 여부 검토 후 대댓글로 승인 및 이용수칙 안내
- 예약 현황을 볼 수단이 없어 교육생은 사용 가능 시간대를 쉽게 알 수 없고, 운영팀은 겹치는 요청을 수기로 조정

**③ 정보 접근성·축적 부재 (도서, 통계, 후기)**
- 오아시스 도서(약 500종)는 반출 금지이나 분실 발생 → 임시 사이트(42gslib)로 목록 열람은 가능하지만 분실 신고·희망 도서 신청 경로는 없음
- 학습 통계(gs42stats)가 별도 주소로 분산 운영
- 42경산 본과정 외 교육과정(경북 특화형 데이터센터 기초과정, 서울대학교 파이썬 AI 교육, 글로벌 기업가 정신 및 AI 몰입 프로그램 등)의 후기가 교육생 전체에 공유되지 않음

**개발자 관점의 해결 필요성**
- 공통 원인: ①비정형 텍스트로 자동 검증·집계 불가 ②현재 상태(예약·신청 처리 현황)를 담는 단일 저장소 부재 ③서비스·정보의 분산
- 개별 기능 단위 개선이 아닌, 정형 데이터 저장소와 인증을 공유하고 교육생 요청 → 운영팀 처리 흐름을 하나로 잇는 통합 시스템 구축이 필요
- 통합 구조는 기능 확장 시 재사용성을 높이고, 차기 기수로의 인수인계도 용이하게 함

## 2. 해결 솔루션 및 핵심 기능 (UI/UX 구상)
서비스의 주요 기능, 사용자 흐름(User Flow), 대시보드 또는 모바일
화면 구상(와이어프레임·스케치)을 담아주세요. 이미지나 다이어그램을
넣어도 좋습니다.

하나의 서비스에 **교육생 화면**과 **교육운영팀 화면**을 두고, 교육생이 요청하면 운영팀이 처리하는 흐름으로 설계했습니다. 화면 시안은 `design/` 폴더에 있습니다. (교육생 5개 · 운영팀 5개 화면, 사이드바 하단 버튼으로 전환)

**기능별 화면 구성**

| 기능 | 교육생 화면 | 교육운영팀 화면 |
| --- | --- | --- |
| 홈 | 다음 면담·회의실 요청·희망 도서·작성할 후기 상태 요약, 후기 요청 알림 배너 | 처리 대기 건수(면담·회의실·도서·후기 작성률), 최근 요청, 오늘 일정 |
| 면담 | 대면 면담 신청(유형: 프리즈·타 사업 참여·기숙사·과제·예비군·기타), 희망 시간 선택, 신청 내역 확인 | 신청 건별 담당자 배정, 희망 일시 확정 또는 다른 시간 제안, 담당자 가능 시간, 유형별 기본 담당자 설정 |
| 회의실 | 캘린더로 날짜 선택, 목적·일시·장소·인원·기타 요청사항 입력 후 예약 요청, 승인 후 이용수칙 팝업 | 요청 승인·반려, 시간 충돌 경고 및 대체 장소 제안, 이용수칙 편집, 장소 목록 관리 |
| 오아시스 도서 | 도서 검색·서가 위치 확인, 분실·훼손 신고, 희망 도서 신청 (대출 기능 없음) | 도서 추가·수정·삭제, CSV 가져오기, 희망 도서 처리 상태 변경, 분실 신고 처리 |
| 교육과정 후기 | 후기 요청 알림을 받은 과정에 후기 작성(익명 선택), 과정별 후기 열람 | 교육과정 등록·참여 학생 추가 → 후기 게시판 생성, 작성률 확인, 미작성자 알림 발송 |
| gs42stats | 기존 통계 사이트 연결 (교육생·운영팀 동일) | 동일 |

**사용자 흐름**
- 면담: 교육생 대면 면담 신청(유형·희망 시간·문의 내용) → 운영팀 담당자 배정 및 일정 확정/조율 → 교육생에게 확정 알림
  - 비대면 면담은 기존처럼 #pedago 채널에서 신청하고 슬랙 DM으로 진행
- 회의실: 교육생 예약 요청 → '승인 대기' → 운영팀 승인(충돌 시 대체 장소 제안) 또는 반려 → 승인 시 이용수칙 팝업·푸시
- 도서: 서가에 없는 책 발견 시 신고 → 운영팀 분실 처리 또는 회수 완료 / 희망 도서 신청 → 검토 중 → 구매 확정·이미 비치됨·반려
- 후기: 운영팀 과정 등록 및 참여 학생 추가 → 과정 종료 후 후기 요청 알림 → 참여 교육생 후기 작성 → 전체 교육생 열람

## 3. 기술 아키텍처 및 구현 로드맵

**기술 스택**

| 구분 | 기술 | 비고 |
| --- | --- | --- |
| Frontend | 리액트 기반 반응형 웹 + PWA | OS 무관, 홈 화면 설치 시 푸시 수신 |
| Backend | Django REST API | 예약 충돌 검증, 신청 상태 관리, 알림 발송 |
| DB | PostgreSQL + Redis | 면담·회의실·도서·교육과정·후기 등 정형 데이터 |
| 인증 | 42 OAuth | 교육생 / 교육운영팀 권한 분리 |
| 알림 | Web Push + Slack | 면담 확정, 회의실 승인·이용수칙, 후기 작성 요청 |
| 배포 | AWS, HTTPS | 푸시 발송에 HTTPS 필수 |

네이티브 앱 대신 PWA를 택한 이유는 안드로이드와 iOS를 별도로 개발하지 않고도 하나의 코드로 푸시 알림까지 제공할 수 있기 때문입니다. (iOS는 홈 화면에 설치한 경우에 푸시를 수신하므로 설치 안내를 함께 제공합니다.)

## 5. 기대 효과 및 캠퍼스 활용 방안

**교육생**
- 면담 신청, 회의실 예약, 도서 검색·신고를 한 곳에서 처리하여 슬랙 문의·답변 대기 감소
- 면담 사유를 공개 채널에 올리지 않고 운영팀에만 전달 가능
- 회의실 예약 현황을 미리 확인해 비어 있는 시간에 요청하고, 처리 상태(승인 대기·승인·반려)를 바로 확인
- 다른 교육생의 교육과정 후기를 참고해 아카데미 프로그램 참여 여부를 판단

**교육운영팀**
- 유형·희망 일시·인원 등이 정형 양식으로 접수되어 재확인 업무 감소
- 면담·회의실·도서·후기 요청을 운영 홈에서 한 번에 확인하고, 담당자 배정·승인·알림 발송까지 한 화면에서 처리
- 회의실 시간 충돌 자동 감지로 중복 예약 수기 조정 감소
- 교육과정별 후기와 작성률이 쌓여 과정 운영 개선 근거로 활용 가능

**42경산 커뮤니티**
- 기수가 바뀌어도 후기와 이용 기록이 남아 경험이 축적됨
- 선배 기수의 후기를 통해 데이터센터 기초과정, 글로벌 기업가 정신 프로그램 등 반복 운영 과정의 참여도 제고 기대
- 교육생이 직접 만들고 사용하며 개선하는 42경산 자치 문화의 사례

**활용 방안**
- 해커톤 이후 핵심 기능(회의실 예약, 면담 신청)부터 파일럿 운영 → 사용자 피드백 반영 → 정식 서비스 전환
- 도입 효과는 #pedago 문의 건수, 회의실 중복 예약 건수, 요청 처리 소요 시간, 후기 작성률의 전후 비교로 확인
